# a-fidelity

## Facts
- Highest-fidelity harness is `FakeSenpiHost`: a hand-written `Bun.listen` unix server inside the test tree, driven by the real `SenpiTransport`/`RpcClient` [test/senpi/fake-host.ts:93].
- Its only seam is the socket path: the transport reads `OMO_BRIDGE_SENPI_SOCKET` and talks to whatever listens there, so the fake replaces the host process, not a module [src/senpi/transport.ts:92].
- The runtime tests point that variable at the fake's socket, so they do run the real client stack [test/http/message-restart.test.ts:63].
- The fake answers ten command types explicitly; every other command gets a blanket `success:true` with no data [test/senpi/fake-host.ts:294].
- Fake handshake data is invented: `instanceId:"fake-host-instance"`, `generation:0`, `engineVersion:"fake"`, three capabilities [test/senpi/fake-host.ts:182]; the live capture adds `serverVersion`, `engineOrdinal`, `launch_profile`, `memory_pressure`, `path_identity_resolver`, `runtimeBuildId` and 51 capabilities [contracts/senpi/live.jsonl:2].
- The fake advertises `subscribe_sessions`, a name absent from the live capture's 51 capabilities [test/senpi/fake-host.ts:187].
- `emit()` writes each event frame to every open socket [test/senpi/fake-host.ts:141], and one real `connect()` opens two connections: RpcClient plus the `AttachClient` raw channel [test/senpi/transport.test.ts:133].
- The transport's own comment records the real constraint the fake does not model: the pinned client drops every frame whose `sessionId` is not the one it holds [src/senpi/transport.ts:115].
- The fake parses newline-delimited JSON and answers synchronously inside the socket `data` handler; there is no delay, queueing, reordering or interleaving control [test/senpi/fake-host.ts:107].
- `finishTurn()` hardcodes `agent_end` then `agent_idle`, so that ordering is asserted by construction, never observed [test/senpi/fake-host.ts:150].
- `get_state` always answers `{sessionId:"rpc-1", paused:false}` [test/senpi/fake-host.ts:241]; the live `get_state` carries ~40 fields including `lifecycle`, `holds`, `ordered` and `isStreaming` [contracts/senpi/live.jsonl:8].
- `open_session` answers `state:{sessionId, paused:false}` with no `isStreaming` [test/senpi/fake-host.ts:210], while the transport seeds `streaming` from exactly that field [src/senpi/transport.ts:207]; the live open answer does carry `isStreaming` [contracts/senpi/live.jsonl:6].
- `get_messages` always answers `[]` [test/senpi/fake-host.ts:221] and `get_entries` ignores `since`/page and always returns `leafId:null` [test/senpi/fake-host.ts:214], while the live host advertises `entries_tail` and `snapshot_cursor` [contracts/senpi/live.jsonl:2].
- `stop()` is a graceful `socket.end()` plus server stop, and that is what the `transport_gone` test triggers [test/senpi/fake-host.ts:155].
- Auth refusal is a scripted in-band `success:false` reply to the very first command [test/senpi/fake-host.ts:166]; the fake never reads `keyRoot`, it only needs a temp dir [test/senpi/fake-host.ts:133], though the live host advertises `auth_key_verify` [contracts/senpi/live.jsonl:2].
- Reconnect is real production code: `attempt()` re-runs `transport.connect()` and then `openSession({sessionPath, retainOnDisconnect:true})` [src/launcher.ts:659].
- The only reconnect test injects a hand-built transport object [test/launcher.test.ts:67] through the `createRuntime` dependency, so no socket, no RpcClient and no raw channel is involved [test/launcher.test.ts:570].
- The surface harness replaces every handler transport through module-level setters [test/senpi/surface-harness.ts:257]; its fakes answer canned data — `prompt` returns `"started"` [test/senpi/surface-harness.ts:158], `setModel` echoes the request [test/senpi/surface-harness.ts:150], and `raw.request` answers `{commands:[]}` for any command [test/senpi/surface-harness.ts:181].
- `wiring.test.ts` substitutes a plain class at `setSessionReadTransport`, and its comment names that as the only seam the http layer exposes [test/http/wiring.test.ts:19].
- The "real client" E2E still swaps in a plain-object transport through the same setters and skips unless `OMO_BRIDGE_E2E_TUI_DIR` is set [test/e2e/real-client.test.ts:93].
- Real-host contact is opt-in and shallow: connect, open, list, state, dispose — no prompt, no event stream, no reconnect [test/senpi/integration.test.ts:73].
- Real captured frames are schema-validated in isolation [test/contract/senpi.test.ts:31] but never replayed through the transport, and no test asserts the fake's answers match them.
- Frame hold-and-replay is tested by calling `dispatch.handle` with hand-built frames, not over a socket [test/http/mount.test.ts:722].
- Multi-session active-state selection is tested against a class fake with a per-session state map; the socket-level fake cannot vary state per session [test/http/session-read.test.ts:361].

## Gaps
- Frame ordering: only a test-chosen order exists, so a host that sends `entry_appended` before `message_end`, or `message_update` before `message_start`, cannot be produced; the hold path is only ever fed the order it assumes [test/http/mount.test.ts:722]. Defect class: assistant rows carrying an invented id or a replayed duplicate — two TUI rows that never merge — and deltas silently lost.
- Connection scoping: because `emit` broadcasts to both sockets and one transport owns two connections, a bridge that consumes the stream from the wrong socket, or from both, still looks correct [test/senpi/fake-host.ts:141]. Defect class: duplicated deltas, doubled usage/cost, events attributed to a session that did not generate them.
- Host death shape: only a clean FIN exists [test/senpi/fake-host.ts:155]; no ECONNRESET mid-frame, no half-written line, no silent hang with the socket open, no new host instance at the same path. Defect class: the bridge reports `attached` forever while nothing arrives, a partial frame kills the dispatcher, or reconnect binds a stale path — the "reconnecting, every route 503" class.
- Reconnect halves: production reconnect re-opens the RpcClient and the session [src/launcher.ts:659], but the fake transport has no raw channel [test/launcher.test.ts:67]; `RawChannel.connect()` returns early while it believes it is connected and only clears on its own disconnect callback [src/senpi/raw.ts:88]. Defect class: after a host restart, session reads recover while slash-command and queue operations over the raw channel stay dead.
- Multi-session routing: `get_state` is a constant and `open_session` records state per connection only [test/senpi/fake-host.ts:241], while runtime resolves host frames to sessions by routing id, `routingId`, then durable id from the transcript path [src/runtime.ts:318]. Defect class: `/api/session/active` marks the wrong session running, a session route serves another session's transcript, or a just-created session's deltas are dropped so it looks frozen.
- Auth failure timing: only the in-band refusal exists [test/senpi/fake-host.ts:166]; a real host can refuse at connect, drop the socket without a response, or answer late, and the live capability set includes `auth_key_verify` [contracts/senpi/live.jsonl:2]. Defect class: a credential refusal is mapped to `transport_gone`, so recovery retries forever and the user sees "reconnecting" instead of an auth error in `/connect`.
- Raw command surface: `attach_session`, `subscribe_sessions`, `dequeue_message`, `edit_queued_message` all fall through to the blanket success [test/senpi/fake-host.ts:294], and the surface fake answers `{commands:[]}` to anything [test/senpi/surface-harness.ts:181]. Defect class: a refused or malformed queue edit/dequeue is invisible — the user's follow-up is edited or removed on the wrong session, or a subscription silently never arrives.
- Error mapping: only `abort` and auth can fail in the fake; real refusals (`unknown_session`, `session_held`, `subscription_limits`) are mapped by `mapSenpiError` [src/senpi/transport.ts:344]. Defect class: a host refusal becomes an empty 200 or an undeclared 500 where the TUI expects 404/409.
- Delivery semantics: the fake never answers `prompt`/`steer`/`followUp` with a disposition [test/senpi/fake-host.ts:294], while the handler maps the host's disposition into the TUI's admission state [src/http/handlers/prompt.ts:215]. Defect class: "queue as steer" behaves as a follow-up, and the inbox row reads running instead of queued, with the suite green.
- Content, not just shape: the surface suite asserts status, content-type and schema only [test/http/surface.test.ts:138] against canned fakes [test/senpi/surface-harness.ts:146]. Defect class: a well-shaped but wrong or empty answer (no models, no commands) ships green — exactly the "no model to select" failure the runtime probe warns about [src/runtime.ts:257].
- Cursors and leaves: `get_entries` always returns the whole transcript with `leafId:null` [test/senpi/fake-host.ts:214], so cursor and leaf semantics are unexercised. Defect class: paging repeats or drops messages, and fork/clone branches from a stale leaf.
- Agent-dir identity: the fake accepts any `keyRoot` [test/senpi/fake-host.ts:133], so a bridge pointed at the wrong agent directory — the other half of the "no models" failure [src/runtime.ts:257] — cannot be observed.
- Connection identity: the sibling-read test asserts against `host.connections[0]`'s frame log, pinning which of the two connections is the streaming one [test/http/session-sibling-read.test.ts:138]; a real host that orders or binds connections differently is not modelled.

## Claims
- No automated test drives the real `RpcClient` against a real host beyond connect/open/list/state/dispose, so production wire behaviour is largely unverified. | [test/senpi/integration.test.ts:73] | high
- The suite's highest-fidelity layer is a hand-written wire server, so a host protocol drift (new required capability, extra handshake field) is invisible until production. | [test/senpi/fake-host.ts:93] | high
- Reconnect, host death and auth-failure handling are tested only through in-process fakes, so their real wire shapes and timings are unproven. | [test/launcher.test.ts:67] | high
- Frame-ordering assumptions are pinned by the tests rather than discovered, so a real ordering difference would surface only in the user's terminal. | [test/http/mount.test.ts:722] | high
- Multi-session state routing cannot fail in any socket-level test, because the fake's `get_state` is a constant. | [test/senpi/fake-host.ts:241] | high
- Wrong-connection consumption and double publication are invisible, because event frames are broadcast to every socket. | [test/senpi/fake-host.ts:141] | high
- Queue/delivery disposition semantics are unverified on the wire, so a steer/follow-up mix-up would pass. | [src/http/handlers/prompt.ts:215] | high
- The surface suite proves HTTP shape, not content, so schema-valid empty model or command answers can pass. | [test/http/surface.test.ts:111] | medium
- The fork's own client contract is exercised only when an external checkout is configured, so default CI proves the bridge against hand-written fetches. | [test/e2e/real-client.test.ts:93] | medium
